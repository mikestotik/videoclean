# BUG-001: Пайплайн удаления завершается COMPLETED, но текст/логотипы не удаляются

Статус: **частично исправлено** (2 корневых бага найдены и починены локально на CPU) · Приоритет: высокий · Компонент: detect → select → segment → inpaint
Дата: 2026-09-07 · Стенд: RunPod RTX 4090, device=cuda; локальное подтверждение — macOS CPU

## Итог расследования (2026-09-07)

**BUG-A (критично, исправлен):** `_or_masks` в `adapters/segmenters/sam2.py` через `while arr.ndim > 3: arr = arr[0]` брал только первую маску из тензора `post_process_masks` формы `(N_box, 1, H, W)`. При нескольких треках маску получал первый бокс, остальные — пустые 0%. SAM2 сам работает верно (сольный вызов того же бокса даёт 27–48% покрытия). Именно поэтому на сервере инпейнтилось «первое попавшееся», а текст оставался. Фикс: разворот всех плоскостей `arr.reshape(-1, h, w)`, тесты `tests/test_sam2_masks.py`.

**BUG-B (высокий, исправлен):** vision-парсер отправлял все 7–8 сэмплов одним запросом. llava-phi3 на 4+ картинках выдаёт бессмыслицу (`"if, if, the frame..."`) — парс падал, ошибка глоталась, молча включался текстовый fallback (`parseMode: "llm"`). С 1–2 кадрами модель отвечает адекватно. Фикс: батчи по 2 кадра (`_VISION_BATCH = 2`) с дедупликацией целей в `adapters/prompt/llm.py`, тесты в `tests/test_llm_parser.py`.

Результат на тестовом ролике (27 кадров, CPU): изменённых пикселей 2.7% → 9.3%, edge-density в зоне заголовка 0.128 → 0.080, parseMode `llm` → `llm-vision`, целей из VLM — чистые `text` / `text [bottom]`.

Прежние гипотезы H1/H3 ниже остались в силе как риски качества (лейбл-«object» и многословные queries), но главные причины были в BUG-A/BUG-B.

## Кратко

Джоба «удали любой текст на видео» (grounding-dino-tiny + sam2-hiera-large + propainter + llava-phi3) завершается `COMPLETED 100% ok`, но в результате остаются и крупный заголовок «ПОРАЖЕНИЕ ПЕРВОГО ТЕПЛОВОЗА», и логотип «ИЗНАНКА ТВ». Маски где-то рисуются (порог покрытия пройден), но явно не по тексту. Локально «местами мылит» — согласуется с масками в случайных местах и дырами по кадрам.

## Анализ цепочки отказа (по коду)

Гипотезы ранжированы по вероятности. Первые три вместе полностью объясняют симптом.

### H1 (критично). Все боксы детектора получают label="object" → селекция пропускает что угодно

- `adapters/detectors/grounding_dino.py:204` — каждый хит жёстко помечается `label="object"`, реальная фраза теряется.
- `application/select.py:112-116` — для целей `text_overlay`/`watermark` любой бокс с лейблом из `_GENERIC_LABELS` (`{"object", ...}`) считается совпадением.

Следствие: если DINO по запросу `text .` выдаёт боксы на чём угодно (дым, строения, разметка) — всё это принимается как «текст», SAM2 режет маски по не тому объекту, ProPainter заливает не то место. Покрытие при этом в норме → guard в `run_cleanup.py:209` молчит → COMPLETED. Это главный кандидат на «ничего не удаляет, но отчёт зелёный».

### H2 (критично). Детекция только на ≤8 ключевых кадрах + template-matching не работает на движущемся фоне

- `grounding_dino.py:77` — DINO запускается максимум на 8 кадрах (`sample_indices(len(frames), min(8, len(frames)))`).
- Остальные кадры добираются шаблонным матчингом кропа: `grounding_dino.py:116-120`, `adapters/detectors/_cv.py:58-83` — шаблон сжимается до 96px и ищется в grayscale с `min_score=0.55`.
- На аэросъёмке фон под статичным текстом непрерывно меняется → корреляция падает ниже 0.55 → `None` почти везде.
- `domain/tracks.py:54-69` (`interpolate_gaps`) заполняет дыры только МЕЖДУ наблюдаемыми боксами. До первого и после последнего ключевого кадра боксов нет вовсе → пустые маски → текст остаётся целыми кусками хронометража. С 8 ключевыми кадрами на длинном видео дыры огромные.

Это объясняет «местами мылит»: на отдельных кадрах маска есть (там совпал шаблон или попал ключевой кадр), на остальных — нет.

### H3 (высокий). VLM-парсер + rewrite схлопывают цель в query "text", который DINO плохо ищет

- Промпт «удали любой текст» → llava-phi3 возвращает цель вида `{kind: text_overlay|object, ...}`.
- `adapters/prompt/refine.py:97-99,128-139` — любая короткая не-физическая object-цель переписывается в `query="text"`; text_overlay → тоже `"text"`.
- Grounding DINO (особенно tiny) слабо локализует generic «text», а кириллические надписи — тем более: скоры ниже порога, остаются случайные слабые боксы → в связке с H1 они принимаются за цель.

### H4 (средний). Verify-проход не спасает

- `run_cleanup.py:235-265` — leftover ищется той же сломанной цепочкой (H1-H3), затем re-inpaint только если покрытие попало в коридор `[min_mask_coverage, max(verify_max_coverage, mean_cov*1.5)]`. При мусорных масках условие легко срезается — «leftover outside …» и пропуск.

### H5 (низкий, вторично). Пороги/фильтры боксов

- `_cv.py:17` — `MAX_BOX_AREA=0.25` может отрезать очень широкий заголовок-плашку (у нас, скорее всего, не тот случай, но проверить).
- `config.py:163` — дефолт 0.15; на скрине не видно, не переопределён ли порог в UI.

## Что НЕ является причиной (проверено по коду)

- ProPainter: вызывается как video_aware, на весь клип (`run_cleanup.py:221-227`), fp16/half — как в официальном репо. Если ему скормить правильные маски, он должен работать. Кривой результат — следствие кривых масок.
- Guard `min_mask_coverage=0.0004` слишком слаб, чтобы поймать проблему: 0.04% покрытия кадра достаточно для COMPLETED.

## План диагностики (следующий шаг)

Артефакты джобы уже на диске: `analysis/` не удаляется при очистке workdir (`run_cleanup.py:331-338` удаляет только frames/inpainted/masks/input/process).

1. Открыть workdir последней джобы и посмотреть:
   - `analysis/prompt.json` — какие queries вышли из llava-phi3 (подтвердить/опровергнуть H3);
   - `analysis/tracks.json` и `tracks_raw.json` — лейблы, `coverage` треков, сколько `null`-боксов по кадрам (H1, H2);
   - `analysis/detector.json` — attempts, каким детектором найдено.
2. Перезапустить с чекбоксом keep_workdir (или CLI `--keep-workdir`) и глазами сравнить `masks/` с кадрами: маска на тексте или на фоне (приговор H1/H2).
3. Микротест детектора: один кадр из видео, query `text .` — что возвращает DINO-tiny при порогах 0.15/0.25, есть ли боксы именно на надписях.

Каждая гипотеза проверяется отдельно по пунктам 1-3, прежде чем что-то чинить.
