# Параметры прогона — полный справочник

Каждый параметр влияет на результат. Здесь: флаг CLI, поле в WebUI (панель «Дополнительно»), дефолт, что делает и когда крутить. Все параметры — независимые оси, никаких «профилей».

Параметры живут в `PipelineConfig` (`videoclean/application/config.py`), валидация там же. Прокидка: CLI (`cli.py`) / WebUI (`adapters/web/fastapi_app.py` → `service.py` → `manage_jobs.py`) → `composition.py` → адаптеры.

## Основные

| Флаг CLI | WebUI | Дефолт | Что делает | Когда крутить |
|---|---|---|---|---|
| `--device` | Устройство | `cpu` (WebUI: авто) | Где крутятся нейросети: `cpu`/`cuda`/`mps` | На GPU-машине всегда `cuda` |
| `--detector` | Детектор | `grounding-dino` | Единственный детектор: grounding-dino |
| `--detector-model` | Модель детектора | `IDEA-Research/grounding-dino-tiny` | HF id модели | См. docs/MODELS.md |
| `--detector-threshold` | Порог детектора | `0.15` | Минимальный скор бокса | Ничего не находит → `0.10`–`0.12`; мусорные боксы → `0.20`+ |
| `--segmenter` / `--segmenter-model` | Сегментатор | `sam2` / `facebook/sam2-hiera-tiny` | Боксы → маски. `sam2` — покадрово, `sam2-video` — пропагация через клип (нужен torch≥2.5) | `sam2-video` лучше для движущихся объектов на CUDA |
| `--inpainter` / `--inpainter-model` | Инпейнтер | `lama` / `camenduru/ProPainter` | Чем заливать: `lama` (нейросеть покадрово, CPU/CUDA), `propainter` (видео-aware, только CUDA) | Финальное качество: propainter на GPU; на CPU — lama |
| `--mask-dilate` | Dilate маски, px | `3` | Расширение SAM-маски | Тонкие буквы остаются по краям → `5`–`8`; большой оверлей «съедает» фон → уменьшить |
| `--min-mask-coverage` | — | `0.0004` | Джоба падает, если средняя маска < доли кадра | Страховка от «молча ничего не удалил». Поднимать при ложных срабатываниях на крошечных зонах |
| `--verify` / `--no-verify` | Проверять leftover | вкл | Verify 2.0: residual + re-detect; локальный re-inpaint проблемных участков | Выключать для скорости на длинных видео |
| `--verify-max-passes` | Verify: проходы | `1` | Сколько раз искать остатки и перезаливать (0 = без re-inpaint) | `2` в профиле quality |
| `--inpaint-workers` | Потоки инпейнта | `0` (auto) | Параллель для LaMa; ProPainter всегда 1 | CPU: auto по ядрам; GPU: обычно 1 |
| `--inpaint-chunk-overlap` | Overlap чанков | `8` | Перекрытие при нарезке video-inpaint / verify | Швы на стыках → поднять |
| `--profile` | Профиль | `custom` | `fast` / `balanced` / `quality` — перебивает segmenter/inpainter/verify knobs | Качество на CUDA: sam2-video+ProPainter |

## Vision-парс промпта (LLM → queries)

| Флаг CLI | WebUI | Дефолт | Что делает | Когда крутить |
|---|---|---|---|---|
| `--prompt-frame-stride` | Кадры для vision, шаг | `4` | Кадр 0, потом каждый N-й. `0` = без vision, только текст | Длинные видео: `8`–`15` |
| `--prompt-frame-max` | Кадры, максимум | `8` | Потолок сэмплов для vision-LLM | Payload в Ollama растёт линейно |
| `--vision-batch` | Vision batch | `2` | Кадров на ОДИН vision-запрос, ответы батчей сливаются | **llava-phi3: строго 2** — на 4+ картинках выдаёт мусор («if, if, the frame»), парс падает в текстовый fallback. Мощные multi-image модели (qwen-vl и т.п.) — можно 4–8 |
| `--prompt-templates <dir>` | — | встроенные | Свой набор промптов-шаблонов: `system.md` (текстовый парс), `vision_system.md` (vision-парс), `bridge_system.md` (спасение, когда vision вернул прозу) | Эксперименты с другими LLM. Не хватает файла — берётся встроенный |

Встроенные шаблоны лежат в `videoclean/adapters/prompt/prompts/*.md` — это единственное место, где «живут» промпты; менять их можно прямо в репо или подменить флагом.

## Детекция и трекинг

| Флаг CLI | WebUI | Дефолт | Что делает | Когда крутить |
|---|---|---|---|---|
| `--detector-keyframes` | Кадры детектора | dino: `8`, owlivit: `12` | На скольких кадрах реально работает нейро-детектор; остальные кадры добираются шаблонным трекингом. Пусто = дефолт детектора | Текст пропадает местами (дыры по кадрам) → `12`–`20` на GPU. CPU: больше — дольше |
| `--detector-nms-iou` | NMS IoU | `0.3` | Дубликаты боксов с пересечением > IoU схлопываются | Много лишних боксов на один объект → `0.2`; разные объекты слиплись → `0.45` |
| `--detector-max-box-area` | Макс. площадь бокса | `0.25` | Боксы > 25% площади кадра отбрасываются (защита от «детектор нашёл полкадра») | Широкие титры-плашки во всю ширину режутся → поднять до `0.35` |
| `--tracker-min-score` | Трекинг: порог | `0.55` | Порог шаблонного матчинга между ключевыми кадрами | Дыры между ключевыми кадрами → снизить до `0.45`; боксы «плывут» по фону → поднять |
| `--tracker-max-template-area` | Трекинг: макс. площадь шаблона | `0.12` | Крупные кропы не трекаются (шаблон цепляется за фон) | Обычно не трогать |

Важно: шаблонный трекинг — grayscale корреляция кропа. На движущемся фоне (аэросъёмка, панорамы) под статичным текстом он работает плохо — следствие: `None`-боксы между ключевыми кадрами, маски пустые, текст остаётся целыми кусками. Лечение: `--detector-keyframes` выше или сегментатор `sam2-video`.

## ProPainter (только CUDA)

Все параметры прокидываются 1:1 в vendor-модель (`data_dir/vendor/ProPainter`).

| Флаг CLI | WebUI | Дефолт | Что делает |
|---|---|---|---|
| `--propainter-mask-dilation` | ProPainter: Mask dilation | `4` | Расширение маски до заливки |
| `--propainter-ref-stride` | Ref stride | `10` | Шаг глобальных референсных кадров |
| `--propainter-neighbor-length` | Neighbor length | `10` | Временное окно соседей |
| `--propainter-subvideo-length` | Subvideo length | `80` | Длина чанка для flow-completion |
| `--propainter-raft-iter` | RAFT iter | `20` | Итерации RAFT-flow. Больше — точнее поток, дольше |

## Константы, которые НЕ вынесены (осознанно)

- Пороги регионов `top/bottom/left/right` (`select.py`: 0.38/0.62, углы 0.45/0.55) — это определения слов «сверху/снизу», а не тюнинг-ручки. Менять = менять семантику промптов.
- `infer_motion` порог дрожания 0.025 (`domain/tracks.py`) — граница static/floating.
- `_PHYSICAL`, `_TEXT_QUERIES`, `_MARK_QUERIES`, `BAD_QUERIES` (`refine.py`, `llm.py`) — словари эвристик перевода целей. Правятся в коде, меняются редко.
- Кэш кадров (`min(48, max(8, n))`) — производительность, на результат не влияет.
- Минимальный размер бокса 4px — внутренний guard.

## Пример: тюнинг под «аэросъёмка + кириллический титр на весь кадр»

```bash
uv run videoclean run \
  --input aerial.mp4 --output out/clean.mp4 \
  --prompt "удали заголовок и логотип канала" \
  --device cuda \
  --detector grounding-dino --detector-keyframes 16 \
  --segmenter sam2-video \
  --inpainter propainter \
  --mask-dilate 6 \
  --detector-max-box-area 0.4 \
  --keep-workdir
```

`--keep-workdir` сохраняет `frames/`, `masks/`, `inpainted/` — смотри глазами, куда легли маски, до того как крутить пороги дальше.

## Scoped parse: чанковый разбор длинных видео

`--parse-chunk-frames` (WebUI: «Чанк парсера, кадров», дефолт `0`).

`0` — один VLM-запрос на весь клип, таргеты действуют везде (поведение до версии scoped). `N > 0` — сэмплы режутся на чанки по N кадров, каждый чанк парсится отдельно, таргеты получают окно кадров `[start, end)`, где они валидны. Соседние чанки с одинаковыми таргетами склеиваются в одно окно.

Когда включать: оверлеи появляются и исчезают в разные моменты (титры сцены, плавающие заставки), а глобальный список врёт — детектор ищет «текст» там, где его нет. Затраты: по одному vision-запросу на батч внутри каждого чанка (`vision_batch` кадров на запрос). Для 10-минутного видео при N=120 и stride=4 это ~25 чанков — держи `vision_batch=2` для llava-phi3.

Как это работает дальше по пайплайну: на ключевом кадре детектор ищет только таргеты, чьё окно покрывает этот кадр; треки обрезаются по окнам до интерполяции (`select.py`). Полный прогон с окнами включается тем же флагом, отчёт (`prompt.json`, `report.json`) показывает `parseMode: llm-vision-scoped` и `frames: [a, b]` у каждого таргета.

## Превью: боксы и маски без инпейнта

Быстрая проверка детекции на подмножестве кадров. Никакого инпейнта, кодирования и verify — только `parse → detect → select → sam2 → оверлеи`.

CLI:

```bash
# разбор + детекция + маски на кадрах 0,4,8,…,60 (LLM-парс)
uv run videoclean preview \
  --input in.mp4 --output ./preview-out \
  --prompt "удали текст и логотип" \
  --llm local --llm-model llava-phi3 \
  --frames 0:16:4

# детекция без LLM по своим таргетам (итерации по секундам)
uv run videoclean preview \
  --input in.mp4 --output ./preview-out \
  --queries "text [bottom], logo" \
  --frames 3,7,15
```

`--frames start:count:stride` или список индексов. Артефакты в `--output` (`jobs/{id}/preview/`): `{индекс}_boxes.jpg` (боксы с id треков), `{индекс}_mask.jpg` (полупрозрачная маска), `preview.json` (queries, таргеты, покрытие по кадрам).

WebUI: панель «Превью» на рабочей странице. Кнопки: «Превью: разбор + маски» (LLM-парс на выбранных кадрах), «Маски по таргетам» (детекция по отредактированному списку таргетов без LLM), «Запустить полный прогон с этими таргетами» (полный пайплайн с `targets_override`, LLM-парс пропускается).

Ограничения превью: инпейнтер не участвует (превью проверяет покрытие масок, не красоту заливки); сегментатор всегда покадровый `sam2`, `sam2-video` в превью не работает (ему нужен весь клип).

## WebUI/API-поля

Поля multipart-формы `POST /api/jobs` (единая точка запуска job'ов из редактора). Базовые параметры пайплайна описаны в разделах выше; здесь — поля маршрутизации и редакторские оверрайды.

| Поле | Что делает | Значения |
|---|---|---|
| `kind` | Тип job'а | `run` (полный прогон) / `preview` (разбор и маски без инпейнта) / `prompt` (интерпретация нарисованных масок через LLM) |
| `source_id` | Видео из библиотеки источников вместо загрузки файла | id из `POST /api/sources`; для `preview` и `prompt` обязателен |
| `targets` | JSON-массив таргетов вместо LLM-парса (`targets_override`) | `[{"kind": "object", "query": "mug"}]`; можно вместе с `masks` (вход C); нельзя с `tracks` |
| `tracks` | JSON-массив готовых треков с боксами (`tracks_override`) | `[{"id", "label", "motion", "boxes": [[x1,y1,x2,y2], …]}]`; нельзя вместе с `targets`/`masks` |
| `masks` | Номера кадров с нарисованными на источнике масками | `2,5,9`; маски берутся из `sources/{id}/masks/`; можно вместе с `targets`/`prompt` (якоря + подпись); нельзя с `tracks` |
| `llm_base_url` | Свой OpenAI-совместимый эндпоинт для парса промпта | URL; пусто = провайдер по `llm_place` |
| `llm_api_key` | Ключ для удалённого LLM-эндпоинта | строка |
| `keep_workdir` | Сохранить рабочую папку job'а (кадры, маски, инпейнт) | `1`/`0` |
| `min_mask_coverage` | Минимальная средняя доля кадра под маской, иначе job падает | float, дефолт `0.0004` |
| `verify_max_coverage` | Потолок leftover-покрытия; выше — re-inpaint пропускается | float, дефолт `0.12` |
| `formats` | Выходные контейнеры через запятую; для `kind=run` пакуются в том же job до `COMPLETED` | `mp4,mov,mkv,webm,hls-fmp4,…`, дефолт `mp4` |
| `webhook_url` | Callback URL: `POST` JSON при `COMPLETED`/`FAILED` (`kind=run`) | HTTPS/HTTP URL |
| `webhook_secret` | HMAC-SHA256 тела; заголовок `X-VideoClean-Signature: sha256=<hex>` | строка |
| `webm_crf` / `segment_seconds` | Параметры упаковки webm / HLS/DASH | int |

Интерактивная схема: `/api/docs` (Swagger), `/api/redoc`. Публичный happy path и auth — в описании OpenAPI и в `GET /api`.

Источники (`POST/GET/DELETE /api/sources/{id}`), покадровые маски-аннотации (`PUT/GET/DELETE /api/sources/{id}/masks/{n}`) и пресеты пайплайна (`GET/POST/DELETE /api/presets`, хранятся в `data_dir/presets.json`) — см. индекс `GET /api`.
